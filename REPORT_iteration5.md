## Part 3 — ledger integrity

**The "unknown" entries** (`docs/findings/ledger-unknown-entries.md`):

- 200 entries, ₹0.50, all with stage `unknown`, model `gemini-3.6-flash`,
  5 prompt / 3 output / 0 thinking tokens.
- Written by `backend/tests/extraction/test_llm_client.py`, which drives
  the Gemini client through an `httpx.MockTransport` with `api_key="fake"`
  and returns exactly that usage. Measured: one run of that file records
  exactly 10 such entries. The smallest real entry has 162 prompt tokens.
- Proven mock (signature + a burst of exactly 10 inside one second): **190
  entries, ₹0.48**, in 19 bursts. One burst of 10 (entries 554–563) spans
  1.7 s, so it is not proven and **stays counted (₹0.03)**.
- One correction entry (`correction_mock_test_entries`, −₹0.48) was
  appended; no entry was edited (history byte-identical, checked).
- Earlier docs called these "embedding calls via generate" and "tests +
  probes"; both now point to the finding.

**Tests vs the real ledger:** the iteration-4 fixture already redirected the
singleton. Now `SPEND_LEDGER_PATH` / `SPEND_PROJECTIONS_PATH` point at tmp
for every test, so even a bare `SpendLedger()` can't resolve to the real
file, and a session guard fails the run if the real ledger or projection log
changes. I proved the guard fires with a throwaway test, then deleted it.

**Embeddings ledgered:** `GeminiEmbeddingClient` checks headroom before each
chunk and records it after (stage `embed_<slug>`). The shortlist "dry-run"
uses the same client, so it is covered. Tested with a mock transport and a
temp ledger only. The API returns no token counts, so tokens are estimated,
and they are priced at an upper-bound rate (the generation input rate) that
**has not been verified** against Google's embedding price. Entries say so.

**Stage gate coded** (`backend/app/extraction/spend_gate.py`): before a
stage, the projection is appended to `data/spend_projections.jsonl` and the
stage is refused if projection ×2 (classification) or ×1.5 (extraction, sync
and batch) exceeds the remaining ceiling. During classification, it halts
once running cost per call exceeds projection ×1.5 (checked from the 3rd
call). Tests use a fake client.

**What remains unexplained:** after the correction the ledger (₹920.79)
still records more than Google's console showed when last checked (₹302 on
2026-10-02). The correction explains ₹0.48 of that. Console lag is the
remaining candidate and is untested. Embedding spend before this run is not
measured.
